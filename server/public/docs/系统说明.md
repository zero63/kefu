## 一、项目概述

kefu 是一套面向企业级客户的 **AI 智能客服系统**，采用多租户 SaaS 架构，提供从访客接入、智能接待、人工服务、工单流转、质检报表的完整闭环。

### 1.1 核心能力

| 能力 | 说明 |
| --- | --- |
| 多渠道接入 | 微信公众号、小程序、API、自定义 webhook |
| AI 智能接待 | 接入百度千帆大模型，关键词 / 负面情绪自动转人工 |
| 三态消息 | sending → delivered → read，保证消息可靠投递 |
| 多租户 | 租户级数据隔离，支持 SaaS 化 |
| 工单流转 | 客服可将会话转为工单跨部门处理 |
| 质检引擎 | 关键词 / 敏感词 / 标准 / 流程 四类规则 |
| 数据报表 | 实时 / 历史 / 客服 / 质检 / 评价 多维度报表 |
| 知识库 | 标准问 + 相似问法 + 命中统计 |

### 1.2 设计目标

- **Windows 单进程可运行**：使用文件 + 进程内映射队列替代 WebSocket，演示环境零依赖
- **生产可水平扩展**：业务逻辑与传输层解耦，Linux 下可平滑切换 Redis Stream / WebSocket
- **多租户零侵入**：每个业务表带 `tenant_id`，中间件自动注入与隔离
- **可观测性**：全链路操作日志、AI 调用日志、敏感词命中日志

### 3.2 请求生命周期（以客服发消息为例）

```
1. 浏览器 POST /api/agent/message/send
   ↓
2. Nginx → Webman Worker
   ↓
3. ResponseMiddleware（统一响应格式）
   ↓
4. AuthMiddleware（验证 JWT Token）
   ↓
5. TenantMiddleware（注入 tenant_id）
   ↓
6. SensitiveFilterMiddleware（敏感词过滤）
   ↓
7. Agent\MessageController::send
   ↓
8. MessageService::agentSend
   ├─ Db::insert（写入 kefu_message）
   ├─ ConnectionManager::pushToSession（推到会话队列）
   ├─ ConnectionManager::pushToRole（推到客服 role 队列）
   └─ 返回 JSON
   ↓
9. 浏览器侧 polling /api/poll/agent 拿到新消息并渲染
```

## 五、数据库设计

### 5.1 数据库基本信息

- **数据库名**：`kefu`
- **账号**：`kefu` / `adminkefu`
- **字符集**：`utf8mb4` / `utf8mb4_unicode_ci`
- **引擎**：InnoDB

### 5.2 表清单（共 47 张表）

按业务模块分组：

| 模块 | 表数量 | 主要表 |
| --- | --- | --- |
| 租户与权限 | 6 | kefu_tenant, kefu_employee, kefu_role, kefu_permission, kefu_role_permission, kefu_dept |
| 客户管理 | 5 | kefu_customer, kefu_customer_group, kefu_customer_tag, kefu_customer_tag_rel, kefu_blacklist |
| 访客端 | 2 | kefu_session_context, kefu_visitor_track |
| 会话模块 | 7 | kefu_session, kefu_message, kefu_evaluate, kefu_leave_msg, kefu_session_tag, kefu_service_note, kefu_quick_reply |
| 机器人 | 9 | kefu_robot, kefu_knowledge, kefu_knowledge_similar, kefu_knowledge_category, kefu_intent, kefu_flow, kefu_flow_node, kefu_entity, kefu_chitchat |
| 工单 | 4 | kefu_ticket, kefu_ticket_log, kefu_ticket_template, kefu_ticket_evaluate |
| 质检 | 2 | kefu_quality_rule, kefu_quality_result |
| 报表 | 3 | kefu_report_daily, kefu_agent_performance, kefu_report_custom |
| 通用 | 9 | kefu_config, kefu_sms, kefu_operation_log, kefu_file, kefu_ai_log, kefu_sensitive_word, kefu_sensitive_log, kefu_internal_msg, kefu_customer_merge_log |

### 5.3 数据库设计原则

1. **所有业务表都带 `tenant_id`**：多租户隔离
2. **主键统一 `id BIGINT AUTO_INCREMENT`**
3. **时间戳字段**：`created_at` / `updated_at`
4. **JSON 字段用 TEXT 存储**：MySQL 5.7 兼容，应用层 JSON 编码 / 解码
5. **软删除**：用 `status` 字段而非 DELETE，保留审计
6. **关键字段加索引**：`session_id`、`customer_id`、`agent_id` 等

### 5.4 初始化脚本

```bash
# 完整初始化（包含测试数据）
mysql -u kefu -p kefu < server/sql/init.sql

# 增量升级
mysql -u kefu -p kefu < server/sql/migration_xxx.sql
```

// 写

$redis->xReadGroup('g1', 'c1', ['queue:'. $uid], '>', 1000);

## 十、AI 智能体接入

### 10.1 百度千帆接入

**客户端**：[server/app/lib/QianfanClient.php](file:///d:/phpstudy_pro/WWW/kefu/server/app/lib/QianfanClient.php)

**正确的两步调用流程**：
```
1. POST /v2/app/conversation  →  返回 conversation_id
2. POST /v2/app/conversation/runs  →  用 conversation_id 调用对话
```

⚠️ **重要**：`conversation_id` 必须通过千帆「新建会话」接口获取，**不能客户端自己生成 UUID**。否则千帆只返回元数据不处理对话。

### 10.2 调用示例

```php
$cli = new QianfanClient($apiKey, $appId);
$r = $cli->chat([['role' => 'user', 'content' => '你好']]);
echo $r['content'];  // AI 回复
```

### 10.3 转人工策略

| 触发条件 | 优先级 |
| --- | --- |
| 访客消息命中转人工关键词累计 N 次 | 高 |
| 命中负面情绪关键词 | 最高 |
| 访客主动调用 handoff 接口 | 最高 |
| AI 调用失败 / 超时 | 中 |

## 十五、常见问题排查

### 15.1 千帆 AI 只返回 conversation_id 没有 answer？

**A**：检查管理后台「AI 智能体」配置中的 `endpoint` 是否为对话接口 `https://qianfan.baidubce.com/v2/app/conversation/runs`（带 `/runs`），不要填成 `https://qianfan.baidubce.com/v2/app/conversation`（新建会话接口）。详见 [server/app/lib/QianfanClient.php](file:///d:/phpstudy_pro/WWW/kefu/server/app/lib/QianfanClient.php) 中的自动修正逻辑。

### 15.2 启动失败

检查 PHP 版本 ≥ 8.0、扩展齐全（pdo_mysql、openssl、mbstring、curl）。查看 `runtime/logs/wm.err`。

### 15.3 数据库连接失败

检查 `server/.env` 中 DB 密码、MySQL 服务状态、用户权限。

### 15.4 消息没推送到客户端

检查 `runtime/push/uid/` 目录是否有新文件，`runtime/push/online/` 查看在线状态。
